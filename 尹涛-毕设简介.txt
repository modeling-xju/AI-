1.毕业设计(论文)题目
AI赋能的软件逆向工程系统设计与实现
2.题目的目的、意义
遗留 Java 系统在长期演进中普遍陷入同一种困境：设计文档缺失或与代码脱节，最初的开发人员陆续离开，代码规模与调用关系却仍在膨胀，系统对外只剩下一个能部署、能运行的黑箱，“某个功能在哪里实现”“为什么这样分层”“改一处会波及哪些模块”，都要靠人重新读代码才能回答。传统逆向方式依靠工程师逐层阅读源码、手工绘制调用图与架构图，周期长、成本高，结论还高度依赖个人经验，换一个人接手往往要从头再来。大语言模型能读懂代码片段，归纳职责、命名模块、撰写说明，但它的输出缺少事实约束，遇到跨文件、跨模块的逻辑就容易给出与代码不符的推测，单独使用不足以支撑工程判断。本项目的做法是把程序分析得到的结构化事实（代码属性图、调用关系、控制流与数据依赖）作为证据底座，把大模型放在语义归纳与文本生成的位置上：结构一侧保证结论有据可查，语义一侧补上“结构本身不说明意图”的缺口，两者结合，才能把散落在源码里的实现细节逐层还原为可复核的功能需求、系统架构与接口文档。这项工作的意义有三层：对工程实践，它为无文档遗留系统的维护、迁移与重构提供了可追溯的理解入口，降低对原作者经验的依赖；对方法研究，它给出了一条“用结构事实约束语义推理”的可行路径，使 AI 辅助逆向的结论可以被检验，而不只是被相信；对后续开发，需求条目与代码证据的对应关系、以及模块依赖矩阵，可以直接作为变更影响分析的输入——改动一处代码，能顺着依赖关系查出会波及哪些功能与模块，让逆向结果参与工程决策，而不是停留在读完即归档的分析报告。
3.主要工作任务
1）仓库接入与预处理模块
- Git 仓库克隆与增量拉取，本地目录、压缩包导入，识别 Maven/Gradle 等多模块工程结构
- 文件扫描与分类（源码、配置、资源、测试），识别语言构成并统计代码规模，筛查出待处理的 Java 工程
- 产出：统一的工程快照与文件清单，作为解析阶段的输入
2）代码结构解析模块
- 用 Joern 将 Java 源码解析为代码属性图（CPG），统一承载语法、控制流与数据流信息
- 抽取调用关系图，整理控制流图（CFG）、控制依赖图（CDG）与数据依赖图（DDG），识别类、方法、字段、接口等实体及其引用关系
- 产出：结构化事实集合，既供知识库入库，也为后续恢复提供基础
3）代码知识库与语义检索模块
- 结构化事实入库，支持按实体、调用链、依赖路径进行图查询
- 代码片段切分并借助嵌入模型向量化，建立向量索引，支持自然语言语义召回
- 图查询与向量检索融合，向恢复模块提供带证据的上下文
- 产出：结构、语义双通道可检索的代码知识库
4）功能需求恢复模块
- 基于社区发现算法对调用图与包、类依赖图聚类，得到候选功能模块
- 结合结构特征与大模型归纳完成模块职责命名，归并相近功能意图，按层级组织功能树
- 生成函数级需求条目，并逐条挂接代码证据（文件、方法、调用链）
- 产出：带证据的功能树与需求条目
5） 系统架构恢复模块
- 分析模块间依赖与跨模块调用路径，识别分层结构与耦合热点
- 抽取关键路径语义，包括系统入口、核心业务流程与外部依赖
- 将架构组件与功能树对齐，输出架构图与依赖矩阵
- 支持变更影响查询：给定类或方法，沿依赖链与证据链输出受影响的功能与模块
- 产出：架构视图与组件—功能映射表
6）文档生成模块
- 依据需求条目与架构视图生成接口文档，按模块、类、方法组织
- 生成面向维护人员的用户手册，按功能树组织操作与配置说明
- 按章节汇总为完整报告，支持导出
- 产出：接口文档、用户手册与完整报告，作为课题的最终交付物
4.关键字：遗留系统；代码属性图；大语言模型；需求恢复；架构恢复
Key words: legacy systems; code property graph; large language model; requirements recovery; architecture recovery
