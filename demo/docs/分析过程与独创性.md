# 分析过程与独创性说明

> 这份文档回答一个答辩必问的问题：**哪些是你设计出来的，哪些只是调用了模型或照搬了别人的做法。**
> 配套文件：`analysis-pipeline.yaml`（分析过程的机器可读声明）、`scripts/render_pipeline.py`（生成二维流水线图）、
> `img/pipeline-2d.svg`（图本身）、`系统框架设计.md`（实现细节）。

## 1. 做法：把「分析过程」写成可核对的声明，而不是一段叙述

`analysis-pipeline.yaml` 把整条链路拆成 8 个阶段，每个阶段都写死四件事：

| 字段 | 作用 |
| --- | --- |
| `tool` | 这一阶段由哪个模块执行，代码里能点开看 |
| `output` | 落哪几张表、产生什么中间产物 |
| `rule` | 这一阶段的判定规则（例如「调用点必须落到具体类」） |
| `paper` | 依据的文献；没有文献依据的，就是本项目自己定的规则 |

另有 `algorithms`（输入 / 输出 / 对照基线 / 指标）、`llm_policy`（模型能做什么、不能做什么）、
`views`（八个页面的二维编码）、`invariants`（硬约束，与设计约束 R1–R17 对应）。

`render_pipeline.py` 只依赖标准库（环境里没有 PyYAML，脚本自带最小 YAML 子集解析），
读这份 YAML 直接画出 `pipeline-2d.svg`：四段式布局「分析阶段 → 算法接入 → 结果展示 → 硬约束」。
**改了声明就改了图，图和实现不会各说各话。**

## 2. 逐阶段：用了什么、依据哪篇、自己加了什么

| 阶段 | 具体做法 | 依据文献 | 本项目的设计点 |
| --- | --- | --- | --- |
| S1 接入与预处理 | Git / 目录 / 压缩包三入口；识别 Maven、Gradle 与模块清单，剔除测试文件 | Chikofsky & Cross 1990 | 三入口统一落到同一 `files` 表；构建方式与语言构成作为后续图的解释变量 |
| S2 结构解析 | Joern 生成 CPG，抽 AST / CALL / CFG / CDG / DDG / REF 六类边 | Yamaguchi et al. 2014（CPG） | 双引擎：`engine=joern` 与自研 `cpg.py` 写同一套表，外部工具不可用时不阻塞 |
| S3 结构入库 | 调用点必须落到具体类；未解析调用只作外部依赖候选 | Kazman et al. 1999（证据法） | 「事实 / 猜测」分表：`calls.callee_id` 为空的一律不进调用图，只进 `externals` |
| S4 检索 | BM25 + LSA 潜在语义（tf-idf 截断 SVD，96 维）与词项点积混合，名次 RRF 融合，叠调用图邻居与功能证据一跳 | Robertson & Zaragoza 2009；Cormack et al. 2009；Deerwester et al. 1990（LSA） | 融合通道额外利用**调用图与功能证据**，而不是只融两路文本分 |
| S5 功能恢复 | Louvain 社区发现；命名由 LLM 或启发式（动词 + 限定词 + 宾语） | Blondel et al. 2008；Hou et al. 2024 | 命名不是唯一出口：无 LLM 时启发式仍给出可读名字；同层不同类强制改名 |
| S6 架构恢复 | 组件 = 模块 × 分层；层间依赖矩阵、入口关键路径、外部依赖 | Kazman et al. 1999；Chikofsky & Cross 1990 | 关键路径把外部依赖与 Feign 远程终点一起画出来，链上能看到「边界在哪」 |
| S7 影响分析 | 沿调用图反向 BFS，支持方法级起点；再补一层「动态推断」边 | Arnold & Bohner 1996 | 静态边之外补接口↔实现同族与反射字面量，动态到达的节点单独标记，不混进静态可达 |
| S8 文档 | 接口文档、用户手册、完整报告，每条结论带行号 | Chikofsky & Cross 1990 | 文档条目必须带 `Class.method` 与行号，可导出单章 |

## 3. 独创性到底在哪

不是「换了个大模型」，也不是「把 A 项目的界面搬过来」，而是下面五条可检验的设计决定：

1. **结构事实与语义结论分权。** 类、方法、调用、边全部由解析器与 Joern 产出；LLM 只允许参与「命名」。
   `llm_policy` 里写明禁止事项：不许生成或修改调用边、不许推断未解析分派、不许算指标。
   这条约束让「模型胡说」不会污染结构事实，也让结果可复现。
2. **证据回指是硬约束，不是提示词。** 功能条目、架构组件、文档段落都保存 `Class.method` 与行号；
   检索结果与影响链都能一键跳到结构页对应位置。评审可以逐条抽查，而不是看一段听起来合理的描述。
3. **双引擎同表。** Joern 与自研解析器写同一套 SQLite 表，下游算法与页面不感知差异。
   这既是对外部工具的依赖风险对冲，也让「小工程秒级、大工程分钟级」有两条路径。
4. **指标对照而不是自证。** 社区发现对照「按 package 划分」的基线（Q / NMI / 内聚），
   检索对照「整串关键词匹配」（Recall@5），影响分析对照「只看 1 跳」。基线弱是已知的，但口径公开、可复算。
5. **图的面积与位置必须携带信息。** 结构/功能的矩形树面积 = 类数 / 条目数；架构矩阵行 = 模块、列 = 分层；
   影响图列 = 跳数。这条规则写进 `invariants`（R11–R13），也是把「文字不可视」改成图的原因。

## 4. 哪些是借用，哪些是自己的

- **借用（明确引用）**：CPG 作为中间表示（Yamaguchi 2014）、Louvain（Blondel 2008）、BM25（Robertson 2009）、
  RRF（Cormack 2009）、基于证据的架构恢复（Kazman 1999）、逆向工程分类（Chikofsky 1990）、LLM4SE 综述（Hou 2024）。
- **自己的**：阶段之间的约束（事实/猜测分表、LLM 边界、证据回指、指标对照口径）、
  双引擎同表、方法级影响、关键路径的外部依赖 + 远程终点、以及八页图谱的二维编码规则。
- **只参考功能、不照搬实现**：界面语言参考过 birdview 与 Software-TransSpect，但只取「左栏统计 + 画布 + 检查器」
  这种信息结构；没有引入 React / Three.js / 3D 透视 / 命令面板，也没有搬它们的页面。

## 5. 还不能吹的部分（自查清单）

- 向量通道已从纯词项升级为「LSA 潜在语义 + 词项」混合（96 维、权重 3:7），但仍不是神经嵌入；
  接入真实 embedding 时只需替换 `_latent_space` 与 `_vector_scores` 两处。
- 大模型命名的**人工抽样**仍是 60 条；为补这个短板新增了全量规则体检（`scripts/eval_naming.py`）：
  SpringBlade 60 条 / minishop 20 条 / smart-medicine 10 条，重名 0，动词开头 91.7% / 80% / 100%，
  中文 100%，长度 ≤12 字 93.3% / 100% / 80%。规则体检不等于人工判断，但至少覆盖了全量。
- 只支持 Java；类型依赖边（权重 0.4）是经验值，没有做敏感性分析。
- 动态分派只覆盖「接口 ↔ 实现」（`I*` 与 `*Impl`）与反射字面量（`forName("a.b.C")`、`getBean(X.class)`）；
  拼字符串、配置驱动、SPI 这类仍然看不到——影响页把它们标成「动态推断」，用户自己决定信不信。

## 6. 二维展示规范（八个页面，每页两个维度）

| 页面 | 维度 | 图形 | 读法 |
| --- | --- | --- | --- |
| 总览 | 模块 × 类数 | 指标条 + 模块卡片 | 先看规模与质量指标 |
| 代码结构 | 目录 × 类数 | 嵌套矩形树 | 面积越大类越多，点块下钻 |
| 功能需求 | 模块 × 条目数 | 嵌套矩形树 + 检查器 | 块 = 模块/条目，右侧看证据 |
| 系统架构 | 模块 × 分层 | 矩阵 | 行是模块、列是分层，格子里是类数与依赖数 |
| 变更影响 | 跳数 × 受影响类 | 分列扩散图 | 列 = 跳数，边 = 调用方向 |
| 语义检索 | 排名 × 得分 | 结果列表 + 证据 | 先看命中，再看证据方法 |
| 评测对比 | 方案 × Recall@5 | 指标表 + 条形 | 四种检索方案横向比 |
| 文档生成 | 文档类型 × 章节 | 分栏预览 | 左目录、右正文，可导出章节 |

## 7. 复现

```bash
cd demo
python scripts/render_pipeline.py        # 由 YAML 生成 docs/img/pipeline-2d.svg
```

浏览器打开 `docs/pipeline-2d.html` 可看同尺寸预览；论文里直接插入 `docs/img/pipeline-2d.svg`。

## 七、语义侧补齐（2026-11-28）

- 向量通道现在是「可插拔」的：有嵌入服务时用稠密向量（`text-embedding-*`），无服务时用 96 维 LSA，二者共用同一套融合与评测代码，`compare` 页会标注 `embed_meta.enabled`。
- 命名评测从「规则体检」升级为「结构证据 vs 只看方法名」的对照：minishop 20 条 95.0% vs 92.5%，SpringBlade 60 条 96.2% vs 78.8%，均值 95.6% vs 85.6%（规则判定口径）。
- 架构报告新增层间依赖矩阵与组件—功能映射，评审可以直接对着表核查「某组件承载哪些功能、跨层调用落在哪」。
- 耦合热点与条目调用链把「架构视图」和「功能视图」接上了：热点组件在图上描边，条目检查器给出一跳调用方/被调方。
